**Pre-registered source-integrity correction; DATA_ONLY/HOLD, NO PROMOTION.** This is not an economic model or a search for improved returns. It is an execution-input bug fix in the original 91-Sunday quote intake and entry-book exporter.

## Failure mode and fixed rule
Tardis' published CSV documentation states that **row order reflects original capture order** and, for exchange events with identical millisecond timestamps, **row position is the tie-breaker**: https://docs.tardis.dev/downloadable-csv-files . Existing I1 code selects a per-symbol last quote using a (local_timestamp, exchange_timestamp) maximum. For two updates with identical local arrival time but different exchange timestamps, this may select an **earlier capture row** instead of the final update. A newer malformed/stale update must invalidate the older book, not revive it. The independent oracles currently repeat the same ordering assumption.

**Precommitted remediation:** require globally nondecreasing local_timestamp within each original Sunday CSV capture, fail closed on any reversal (do not silently reorder original records), and select the **last physical row per symbol** in the 5-minute decision window, including invalid rows. On identical arrival timestamps, the later physical row wins regardless of exchange timestamp; it may revoke the earlier quote. Keep all existing exchange<=arrival, venue freshness, original SHA256, price grid, native creation, 91-week, five-fold and partition checks unchanged. No forward/validation/holdout data. Apply the rule to both primary paths and independently reimplement it in both byte-level oracles. A fixture with same-arrival, lower-exchange-timestamp invalid final quote must reduce 182 synthetic pairs to 181; a decreasing-arrival capture must be rejected, not re-sorted. Independent export parity and original-byte tamper rejection must pass.
