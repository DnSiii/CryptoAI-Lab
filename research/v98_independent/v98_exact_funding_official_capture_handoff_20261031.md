# V98 Independent — authorized official event mark capture handoff (2026-10-31)

This is **executable capture code, not a completed data acquisition**. Script: `v98_exact_funding_official_capture.py`. It requests only Binance's documented USD-M `/fapi/v1/fundingRate` endpoint for BTCUSDT, ETHUSDT, BNBUSDT, SOLUSDT, Dec-2022 through Dec-2024, with 1,000-row pagination and an exact 2,286-event-per-symbol slot gate. It writes unmodified HTTP JSON page bodies, SHA256 per page, UTC request/response timestamps, selected response headers, assembled per-asset JSON, strict V98 importer-compatible manifest, and an explicitly **unverified** operator transport receipt.

On a network where the official endpoint is lawfully accessible, run `python research/v98_independent/v98_exact_funding_official_capture.py --output-dir ./v98-exact-native-capture` in an **empty** output directory. It fails closed on HTTP errors, missing fields, invalid marks, wrong symbol, duplicate/missing/off-calendar slots, non-JSON response or incomplete 4×2,286 coverage. The source URL is hardcoded to the official endpoint; no third-party mirror is silently accepted. The `--self-test` and `--dry-run` modes never access the network and **cannot** certify funding.

After capture, an independent auditor must verify source/transport identity and raw bodies, then run `v98_exact_funding_event_ingest.py` against the pinned Clean-4 source and official hourly envelope. The importer still must independently reconcile all native rates and exact event marks. Operator-provided HTTP logs and SHA values alone are **not** cryptographic exchange-origin proof. The current GitHub runner has returned HTTP451/202/400 or timeouts from official candidate hosts; this new capture code cannot bypass jurisdiction/network restrictions.
